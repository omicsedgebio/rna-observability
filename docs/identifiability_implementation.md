# Structure-independent identifiability implementation

The Ensembl 91 GTF defines the mandatory annotation-only baseline. `src/rnaobs/core.py` segments each gene's exon union at every boundary and records which transcript columns contain each segment. Junctions add separate incidence rows. It computes isoforms per gene, exon count, unique exonic bases, shared-exon fraction, unique junction count, maximum pairwise exonic Jaccard similarity, identical splice-chain count, incidence rank and rank deficiency, genomic span and mean exon length. This binary incidence matrix is an **annotation-derived approximation**, not a read-level compatibility matrix or miniQuant K-value.

The exact 31-mer utility `src/exact_kmers.cpp` counts transcript-specific unique canonical k-mers across the complete validated Ensembl 91 transcript FASTA. A k-mer is unique when its sequence or reverse complement occurs in only one transcript identity; repeated occurrences within that transcript count once. ACGT-only windows are valid. The resulting fraction is transcript-unique distinct 31-mers divided by all distinct valid 31-mers in that transcript; transcripts shorter than 31 nt are missing. This is not an aligner-mappability estimate, because substitutions, errors and strandedness are not modeled. Exact-sequence duplicates are retained as groups, not broken apart.

The original [miniQuant source](https://github.com/Augroup/miniQuant) was pinned at `c1b5a89f3c31c83b271a477475a1e289ee9806d7`. Its license file is PolyForm Noncommercial 1.0.0. The full upstream build failed locally because static ggcat libraries were absent. `scripts/run_miniquant_kvalue.py` instead compiles the original annotation parser, region generator, K-value calculator, file writer and utility source with a minimal driver, without changing the algorithm. Parameters: fragment length 235, effective-length entry type, two threads, Ensembl 91 GTF. The original K-value table contains 58,302 gene rows; 191,286 of the 199,216 sequence-feature transcripts have an available gene K-value. This is the **original miniQuant gene K-value calculation**, not a reconstruction or transcript-level K-value. Its interpretation and cross-platform applicability remain sensitivity questions; it cannot replace exon and sequence controls.

`scripts/phase3a_feature_audit.py` combines these independent-of-outcome features into the ignored local derived table `results/tables/identifiability_sequence_features.tsv`. The audit summary records missingness and cross-gene exact-sequence duplicates. No structure score or platform disagreement enters any feature calculation. A 31-mer uniqueness control and miniQuant K-value are distinct and should both remain in future Model B/C sensitivity. Future refits must use identical transcript rows across models.
